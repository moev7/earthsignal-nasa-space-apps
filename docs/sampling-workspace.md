# 🧮 From image reviews to an honest area estimate

Open **Scientific explorer → Explore sampling & uncertainty**, or visit
`/sampling-lab`. Collaborator sign-in protects the workspace, history and downloads.
The ordinary place-and-question experience and existing tools remain available.

## A first experiment

1. Choose **Try the made-up example**. Nothing has been uploaded yet.
2. Inspect the category definition and exact JSON under **Check before sending**.
3. Choose **Run private experiment**. The existing science worker processes it.
4. Read **What was counted**, **What can be estimated** and **What still needs checking**.
5. Change units, inspect sampling groups and download the original input, full
   result, category CSV and provenance manifest. Print the brief to PDF.

The example samples a small group more heavily. Counting reviews gives 22% for
category A; weighting by group size gives 13%: 52,000 m², or 5.2 ha. Estimated
**sampling standard error** is about 20,123.83 m². These are fictional categories,
not environmental measurements.

**Try an unfinished review** demonstrates abstention: one unknown selected answer
withholds the area estimates and sampling uncertainty. Unknown is not classified
as no change or dropped from the denominator. The separate
[singleton input](../examples/stratified-area-demo/singleton-input.json) demonstrates
a point estimate with unavailable sampling uncertainty. The committed result
fixtures were generated by the unchanged native calculator.

## Bring your own experiment

Choose UTF-8 JSON in the [versioned format](stratified-area.md). It needs a declared
equal-area cell frame, sampling-group populations, selected cells, category
definitions, every recorded outcome, source hashes and freeze dates. The limit
is 2 MiB. The server checks the full contract before calculating anything.

Image-review drafts do not automatically establish a probability-sampling design,
field truth or appropriate labels for another sensor/date. No automatic conversion
or scientific promotion is performed. An external-review declaration remains a
declaration, including in exports.

## Read uncertainty correctly

Sampling SE describes variation caused by selecting some cells instead of all
cells. It does not quantify interpretation errors, mismatched sources/dates or
ground-area distortion. It appears separately, without a combined confidence
score, probability of danger or invented confidence interval.

The full JSON retains covariance matrices, inputs, hashes, method version,
unknown counts and withholding reasons. Area exports retain m²; display conversion
and printing do not change analytical inputs. A cell-category footprint is not
continuous water or vegetation coverage within each cell.

## Private, bounded processing

`/api/area-experiments` uses the signed gateway and single worker. History, detail,
cancellation and downloads are owner-scoped. Private input never goes to Gemini
or another AI. Exact submitted bytes determine identity. Reusing the idempotency
key and bytes returns the same job after completion, failure or cancellation;
changing them produces a conflict.

Only the exact POST collection allows 2 MiB; other service requests retain 16 KiB.
The web gateway reserves at most two submission slots through upstream completion.
Queue, user, daily, runtime and storage limits are shared with other analyses.

Raw requests live in SQLite only while queued/running. Every terminal transition
atomically replaces them with a source hash and byte count. Successful inputs
and full results live in expiring service artifacts; history holds a compact
manifest. Queued inputs expire after the configured runtime plus 60 seconds
during service activity. Interrupted jobs fail without retry. Ordinary results
expire seven days after their terminal transition.

`secure_delete` is defense in depth. Row compaction is not guaranteed physical
erasure from WAL files, backups, filesystem snapshots or a stopped service.
Storage accounting includes database/WAL files, staging, results and outstanding
area-job reservations. No automatic vacuum or backup deletion is performed.

The worker reproduces artifacts from the original input before atomic publication.
Downloads check ownership, expiry, file type, byte size and SHA-256. Altered or
missing artifacts are withheld. CSV labels that could execute spreadsheet
formulas are escaped; JSON retains original category IDs.

## Activation and remaining evidence

`EARTHSIGNAL_AREA_EXPERIMENTS_ENABLED=true` enables new submissions; the default is
false. Disabling it preserves history, cancellation and unexpired exports.
Drain/cancel area jobs before rolling back to code without the new job kind.
Never restore an old database over later jobs.

Independent reference qualification, untouched evaluation and the planned human
comprehension sessions remain separate gates. Browser QA does not establish that
twelve representative users understood the tool.

SQLite's [official WAL documentation](https://www.sqlite.org/wal.html) records a
rare concurrent WAL-reset defect fixed in 3.51.3 and later, with named backports.
Check actual runtime and distributor patches before activation. The operator
activated a service-scoped official 3.54.0 build after native checks, integrity
verification, supervised rollback and resource receipts. Both science processes
were checked through their loaded-library mappings; this does not replace the OS
library or establish the web process's SQLite version.

The [isolated build recipe](../scripts/build-science-sqlite-3.54.sh) verifies the
official SHA3-256 source pin. Run compilation inside a transient systemd unit
with explicit CPU/memory limits. It does not activate a service or replace the
OS library. The initial server build took 63 seconds at a 25% CPU cap, with
192 MiB resident memory and 258 MiB peak swap; these are build costs, not job
runtime measurements. WAL/integrity smoke checks and GTiff/HDF5/HDF5Image/GPKG
driver loading passed under the isolated runtime before activation.

The [pinned source activation recipe](../scripts/activate-science-area-r22-20261014.py)
uses the existing compensated source-swap protocol: reject nonempty admission,
verify package/components, back up the database, smoke the candidate, restore
the previous code and actual units, then activate. It never overwrites later
database state. Its source flag stays disabled until separate operational checks
permit new submissions. Web and runtime activation require their own receipts.

### Deployed verification — 14 October 2026

The science source `area-workspace-r22-20261014` is active and new experiments are
enabled on `nasa.r8volt.com`. Source and web activation each exercised an actual
supervised rollback before final activation, without restoring an earlier database
over new state. Local operator receipts are retained under
`/var/backups/earthsignal-science/`; they are not public artifacts or credentials.

Production HTTP checks verified anonymous denial, protected page access,
cross-owner denial for status, cancellation and downloads, the exact 2 MiB upload
boundary, the original 16 KiB limit for other submissions, terminal idempotency and
byte-for-byte source downloads. Eight concurrent maximum-size submissions with
one idempotency key returned two 202 responses and six 429 responses, with one
unique job. The completed synthetic example reproduced 13% and 52,000 m² with
sampling SE 20,123.827196948187 m². These are software checks of fictional data.

One initial Node HTTP/2 client attempt received a transport reset. The subsequent
bounded verification completed without resets; no transport root cause or server
protocol repair is claimed. Desktop/mobile browser checks used the actual page,
gateway and native worker in a local fixture. Protected production page/API checks
were separate HTTP checks, not a claim of production browser authentication QA.

After load, database integrity was `ok`, no jobs were queued/running, and all 128
original artifact hashes were unchanged. Observed cgroup peaks were 293,011,456
bytes for science and 117,157,888 bytes for web, below their respective 384/192 MiB
limits. Both retained their half-CPU caps. These bounded checks do not establish
capacity for arbitrary workloads or a larger server.

The round's full web suite passed 206 tests, TypeScript and the build passed, and
independent Codex Sol/Luna reviews were accepted after coordinator checks. The
preceding backend release's three CI jobs passed, including Python 3.12 and native
GDAL suites. New-input/old-result races have explicit shipped-script regression
tests: preparing an input hides older results, late responses cannot reopen them,
and history can reopen them deliberately. Independent field validation and human
